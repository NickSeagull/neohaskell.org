# NeoHaskell homepage brief

Status: the owner approved implementation with “good, lets go” after the scope correction. The homepage and static documentation entry pages are now built locally. The interactive study remains a visual reference, not a homepage feature specification. GitHub Pages is configured but not deployed.

- **Job and outcome:** Introduce NeoHaskell to prospective application builders and lead them into documentation. Visitors learn commands, decisions, events, and queries there before installing NeoHaskell and using an AI agent. Assume no Haskell or architecture expertise. The implemented CTA, “Learn the concepts”, opens the documentation introduction.
- **Visual direction and vocabulary:** Preserve the exact name and logo, the selected workshop composition, Violet + electric cyan dark mode, and Daylight + violet ink light mode. Use the Event ledger component language and canonical **commands, decisions, events, queries** from `GLOSSARY.md`. Ecommerce is the example domain; the current illustrative sequence is **Place order → In stock? → OrderPlaced → Stock remaining**.
- **Homepage animation:** Show one short opening sequence: the command reaches a decision, `OrderPlaced` joins the ledger, and the stock query changes from three mugs to two. Play once and settle into a readable still composition. Show the completed composition for reduced motion. No concept stepping, scenario selector, lesson narration, learning-path module, or explainer-widget controls on the homepage.
- **Page and documentation boundary:** Keep the homepage focused on the product promise, initial animation, concise supporting copy, and entry into documentation. Documentation carries the concept explanations and ecommerce examples, followed by installation and AI-agent setup. Its detailed lesson structure and interactivity remain outside this homepage brief. The prototype's sold-out case and controls are reference material, not approved website requirements.
- **Delivery:** Use Astro Starlight and GitHub Pages. Follow the selected image comps for landing-page composition; documentation uses code first. Keep animation lightweight, responsive, and compatible with reduced motion. Verify product claims and installation commands before publication. Preserve the five standard UTM fields through entry and documentation navigation within the static site's capabilities.
