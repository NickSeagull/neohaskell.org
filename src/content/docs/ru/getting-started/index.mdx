<p class="docs-lead">Подготовьте среду и задайте ИИ-агенту первую небольшую и четко определенную задачу.</p>

Если команды, решения, события и запросы вам незнакомы, начните с [основных понятий](/learn/). В этом руководстве используется тот же пример магазина: принять заказ, если товар есть на складе, и отклонить его, если он закончился.

## Подготовьте среду

**Neo CLI** создает, собирает, запускает и тестирует приложение. В [системных требованиях и инструкциях по установке](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/README.md#prerequisites) указаны Nix и Git. Для описанного способа установки из исходного кода также понадобится Cargo из Rust. Следуйте [руководству по созданию и запуску проекта](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/project-and-cli.md#create-and-run-an-application), чтобы создать репозиторий приложения до установки навыков для ИИ-агента.

Чтобы сначала изучить приложение Counter, прочитайте [требования и краткое руководство по запуску стартового проекта](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/starter/README.md#requirements). По умолчанию в нем используется хранилище событий в памяти: записанные события исчезают после завершения процесса. В [руководстве по хранению данных](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/storage.md) описаны варианты постоянного хранения.

Эти ссылки описывают проверенную версию фреймворка. Используйте инструкции, соответствующие версии, зафиксированной в вашем приложении. Для установки навыков отдельно требуется **Node.js версии 22.20 или новее**.

Прежде чем продолжить, откройте репозиторий приложения и подготовьте среду разработки, в которой будет работать ваш ИИ-агент. Текущая коллекция навыков поддерживает **Claude Code** и **Codex**.

## Установите навыки для ИИ-агента

Навыки NeoHaskell дают вашему ИИ-агенту инструкции для работы с проектом. Выполните эту команду из корневой папки Git вашего приложения:

```sh title="Терминал" wrap
npx skills add neohaskell/skills --skill '*'
```

Установщик спросит, для какого агента и в какой области установить навыки. Выберите всю коллекцию, чтобы связанные навыки и материалы были доступны вместе. Храните установленные файлы и файл блокировки зависимостей вместе с проектом.

Команда и системные требования взяты из [README навыков NeoHaskell](https://github.com/neohaskell/skills/blob/0ff0872d554e79d955f4c92f9b905056b908e9ae/README.md), проверенного 9 ноября 2026 года. Обновления ищите в [текущих инструкциях по установке](https://github.com/neohaskell/skills#readme).

## Опишите первую задачу

Опишите ИИ-агенту нужное поведение, в том числе что должно происходить, если команду нельзя принять. Для примера магазина можно использовать такую задачу:

```text title="Пример задачи для ИИ-агента" wrap
Позволь клиенту заказать одну керамическую кружку.

Принимай заказ, только если количество положительное и товара достаточно на складе.

Записывай принятый заказ как OrderPlaced и добавь запрос, возвращающий остаток на складе.

Если товара недостаточно, отклоняй команду и не записывай событие принятого заказа.

Проверь оба исхода: принятие и отклонение заказа.
```

Начните с этого поведения. Добавляйте оплату, доставку и другие условия отдельно, когда сможете проверить первый результат.

## Проверьте результат

Попросите ИИ-агента показать принятый и отклоненный заказ. Для каждого случая возьмите начальный остаток из таблицы и сравните результат с моделью.

| Начальный остаток | Команда | Ожидаемое событие | Остаток после |
| --- | --- | --- | --- |
| 3 кружки | Заказать 1 кружку | `OrderPlaced` | 2 кружки |
| 0 кружек | Заказать 1 кружку | Событие принятого заказа отсутствует | 0 кружек |

Также проверьте, что заказы с нулевым или отрицательным количеством отклоняются. Технические проверки помогают находить ошибки реализации. Вам решать, соответствует ли поведение требованиям вашего приложения.

Если результат вас удивил, объясните ИИ-агенту, что именно отличается, используя те же понятия: команда, решение, событие и запрос. Так будет понятно, какое поведение нужно исправить.

Информацию о синтаксисе, тестировании, примечаниях к выпускам и помощи ищите в разделе [Ресурсы и состояние проекта](/resources/).
