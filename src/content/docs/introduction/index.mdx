**A developer's value has never been memorizing APIs or getting syntax right.** It lies in understanding a problem well enough to build something that solves it. That means asking questions, finding contradictions, and pursuing the uncomfortable details that change what the software must do.

AI makes writing an implementation easier. It makes that judgment more valuable. An agent can produce a checkout screen from a short description; deciding what the shop promises when someone presses its button takes an understanding of the business.

NeoHaskell is built around this view of development. **One person should be able to understand and build a whole application**, with tools that support their judgment and make the work enjoyable. That is why the language includes the tools for building an application, and why AI belongs at the center of its design.

## The questions that change the software

Consider a shop owner asking for online orders. Three ceramic mugs remain on the shelf. The request sounds simple until a developer starts asking what buying one actually means:

- Does adding a mug to a basket make it unavailable to other customers?
- Does the shop promise the mug when it accepts the order or when payment arrives?
- If an order is cancelled, when does its mug become available again?
- What should happen when a customer orders more mugs than remain?

These questions reach beyond a checkout screen. They connect the customer's expectations to the work of the person packing orders and the owner handling refunds. Those people may use the same word, "order," for different moments in the process.

**Discovering and resolving that disagreement is software development.** The answer determines what the application must remember, what it must prevent, and what it must tell each person. Writing code before asking the question simply hides an unspoken business decision inside an implementation.

This is demanding work. It requires listening, challenging assumptions, and following a process through its exceptions. An agent makes it easier to act on that understanding. The understanding is what gives the resulting software its value.

## A language that takes on the assembly work

That judgment deserves attention. Spending it repeatedly choosing how to store changes, connect libraries, and organize each new feature leaves less for the application itself.

NeoHaskell makes those recurring technical choices. It provides a common path for checking a proposed change, recording what happened, and updating the answers shown on screens. The developer defines the shop's policy; NeoHaskell supplies the machinery that applies it.

For example, a stock policy should have one implementation even when orders arrive through a website and an AI tool. NeoHaskell gives those interfaces a shared path through the same business decision. Adding an interface does not mean inventing another place to enforce the policy.

**We build these capabilities into the language because one person should not have to become a specialist in every layer to build a useful application.** Shared conventions also give an agent a structure to work within and give the developer a structure in which to review its changes.

## Enjoy building something that makes sense

NeoHaskell treats developer happiness as a design priority. There is pleasure in untangling a difficult process, expressing it clearly, and seeing the application do what was intended. The tools should leave more room for that work.

To keep business understanding close to implementation, NeoHaskell uses a method called **Event Modeling**. It connects what people want to do, what actually happens, and what they need to see afterward. Those same concepts organize the application, so the reasoning agreed with the shop owner has a recognizable place in the code.

Whether an agent writes the implementation or a developer writes it by hand, the basis for judging the result stays concrete: the customer's request, the shop's promise, and the behavior they agreed on. That is what makes a generated change something a developer can understand and take responsibility for.
