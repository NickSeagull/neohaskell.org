## Page plan

This page will separate who is acting from what that person or process may do. It will show the framework's documented identity and authorization mechanisms through one allowed command, one denied command, and a query with restricted access. A decision table will compare actor, resource, permission, and outcome without relying on color. Small source excerpts and tests will demonstrate where access checks belong, while [Resources](/resources/#before-relying-on-an-application) provides the existing authorization guidance.
