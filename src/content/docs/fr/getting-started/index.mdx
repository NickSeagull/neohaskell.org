<p class="docs-lead">Préparez votre environnement et confiez à votre agent d’IA une première tâche clairement délimitée.</p>

Commencez par [Le travail derrière le code](/introduction/) si les commandes, les décisions, les événements et les requêtes sont nouveaux pour vous. Ce guide reprend le même exemple de boutique : accepter une commande lorsque le stock est disponible et la rejeter lorsque la boutique est en rupture de stock.

## Préparer votre environnement

La **CLI Neo** crée, compile, exécute et teste une application. Ses [prérequis et instructions d’installation](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/README.md#prerequisites) indiquent Nix et Git ; l’installation depuis les sources documentée utilise aussi Cargo de Rust. Suivez le [guide de création et d’exécution d’un projet](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/project-and-cli.md#create-and-run-an-application) pour créer le dépôt de votre application avant d’installer les compétences pour agents.

Pour examiner d’abord l’application Counter, lisez les [prérequis et le guide de démarrage rapide du projet de départ](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/starter/README.md#requirements). Son magasin d’événements est en mémoire par défaut : les événements enregistrés disparaissent à l’arrêt du processus. Le [guide du stockage](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/storage.md) explique les options de stockage persistant.

Ces liens décrivent la révision du framework examinée. Suivez les instructions correspondant à la version figée dans votre application. Le programme d’installation des compétences pour agents nécessite séparément **Node.js 22.20 ou une version ultérieure**.

Avant de continuer, ouvrez le dépôt de votre application et préparez votre agent de programmation à y travailler. La collection actuelle de compétences prend en charge **Claude Code** et **Codex**.

## Installer les compétences pour agents

Les compétences NeoHaskell fournissent à votre agent de programmation des conseils adaptés au projet. Exécutez cette commande depuis la racine Git de votre application :

```sh title="Terminal" wrap
npx skills add neohaskell/skills --skill '*'
```

Le programme d’installation vous demande quel agent et quelle portée d’installation utiliser. Choisissez la collection complète pour que les compétences et ressources associées soient disponibles ensemble. Conservez les fichiers installés et le fichier de verrouillage dans votre projet.

La commande et les prérequis du programme d’installation proviennent du [fichier README des compétences NeoHaskell](https://github.com/neohaskell/skills/blob/0ff0872d554e79d955f4c92f9b905056b908e9ae/README.md), vérifié le 9 novembre 2026. Consultez les [instructions d’installation actuelles](https://github.com/neohaskell/skills#readme) pour connaître les mises à jour.

## Décrire une première tâche

Indiquez à l’agent le comportement attendu, y compris ce qui doit se passer si la commande ne peut pas être acceptée. Vous pouvez utiliser cette tâche pour l’exemple de la boutique :

```text title="Exemple de tâche pour votre agent" wrap
Permets à un client de commander une tasse en céramique.

Accepte la commande uniquement si la quantité est positive et si le stock est suffisant.

Enregistre une commande acceptée sous la forme OrderPlaced et fournis une requête pour le stock restant.

Si le stock est insuffisant, rejette la commande sans enregistrer d’événement de commande acceptée.

Vérifie les résultats acceptés et rejetés.
```

Commencez par ce seul comportement. Ajoutez les paiements, l’expédition et les autres conditions dans des modifications distinctes, une fois que vous pourrez vérifier le premier résultat.

## Vérifier le résultat

Demandez à l’agent de montrer une commande acceptée et une commande rejetée. Pour chaque cas, partez du stock indiqué ci-dessous et comparez le résultat au modèle.

| Stock initial | Commande | Événement attendu | Stock ensuite |
| --- | --- | --- | --- |
| 3 tasses | Commander 1 tasse | `OrderPlaced` | 2 tasses |
| 0 tasse | Commander 1 tasse | Aucun événement de commande acceptée | 0 tasse |

Vérifiez aussi que les quantités nulles ou négatives sont rejetées. Les contrôles techniques aident à repérer les erreurs d’implémentation ; c’est à vous de décider si le comportement correspond à celui attendu de votre application.

Si le résultat est inattendu, décrivez la différence à l’agent avec le même vocabulaire : la commande, la décision, l’événement et la requête. Vous indiquerez ainsi précisément quel comportement corriger.

Pour la syntaxe, les conseils sur les tests, les notes de version ou l’aide, consultez [Ressources et état du projet](/resources/).
