<p class="docs-lead">Prepare o seu ambiente e atribua ao agente de IA uma primeira tarefa pequena e bem definida.</p>

Comece por [O trabalho por detrás do código](../introduction/) se os comandos, as decisões, os eventos e as consultas ainda são novos para si. Este guia usa o mesmo exemplo da loja: aceitar uma encomenda quando há stock disponível e rejeitá-la quando a loja está sem stock.

## Prepare o seu ambiente <a id="prepare-your-environment" />

A **CLI Neo** cria, compila, executa e testa uma aplicação. Os seus [pré-requisitos e instruções de instalação](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/README.md#prerequisites) indicam Nix e Git; a instalação a partir do código-fonte documentada também usa o Cargo do Rust. Siga o [guia de criação e execução de projetos](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/project-and-cli.md#create-and-run-an-application) para criar o repositório da aplicação antes de instalar as competências do agente.

Para começar por inspecionar a aplicação Counter, leia os [requisitos e o início rápido do projeto inicial](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/starter/README.md#requirements). O seu armazenamento de eventos predefinido é em memória: os eventos registados desaparecem quando o processo termina. O [guia de armazenamento](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/storage.md) explica as opções de armazenamento persistente.

Estas ligações descrevem a revisão do framework inspecionada. Use as instruções correspondentes à versão fixada pela sua aplicação. O instalador das competências do agente requer, separadamente, **Node.js 22.20 ou posterior**.

Antes de continuar, tenha aberto o repositório da aplicação e deixe o agente de programação pronto para trabalhar nele. A coleção atual de competências é compatível com **Claude Code** e **Codex**.

## Instale as competências do agente <a id="install-agent-skills" />

As competências NeoHaskell dão ao seu agente de programação orientações específicas para o projeto. Execute este comando a partir da raiz Git da sua aplicação:

```sh title="Terminal" wrap
npx skills add neohaskell/skills --skill '*'
```

O instalador pergunta que agente e âmbito de instalação deve usar. Selecione a coleção completa para disponibilizar em conjunto as competências e os recursos relacionados. Mantenha os ficheiros instalados e o ficheiro de bloqueio no projeto.

O comando e os requisitos do instalador vêm do [README das competências NeoHaskell](https://github.com/neohaskell/skills/blob/0ff0872d554e79d955f4c92f9b905056b908e9ae/README.md), consultado a 9 de novembro de 2026. Consulte as [instruções de instalação atuais](https://github.com/neohaskell/skills#readme) para obter atualizações.

## Descreva uma primeira tarefa <a id="describe-a-first-task" />

Diga ao agente que comportamento pretende, incluindo o que deve acontecer quando o comando não puder ser aceite. Pode usar esta tarefa para o exemplo da loja:

```text title="Tarefa de exemplo para o agente" wrap
Permite que um cliente encomende uma caneca de cerâmica.

Aceita a encomenda apenas quando a quantidade é positiva e há stock suficiente.

Regista as encomendas aceites como OrderPlaced e disponibiliza uma consulta para o stock restante.

Se não houver stock suficiente, rejeita o comando sem registar um evento de encomenda aceite.

Verifica os resultados de aceitação e de rejeição.
```

Comece com este único comportamento. Acrescente pagamentos, expedição e outras condições como alterações separadas depois de conseguir verificar o primeiro resultado.

## Verifique o resultado <a id="check-the-result" />

Peça ao agente para demonstrar uma encomenda aceite e outra rejeitada. Em cada caso, comece com o stock abaixo e compare o resultado com o modelo.

| Stock inicial | Comando | Evento esperado | Stock final |
| --- | --- | --- | --- |
| 3 canecas | Encomendar 1 caneca | `OrderPlaced` | 2 canecas |
| 0 canecas | Encomendar 1 caneca | Nenhum evento de encomenda aceite | 0 canecas |

Verifique também se as quantidades iguais ou inferiores a zero são rejeitadas. As verificações técnicas ajudam a detetar erros de implementação; continua a ser sua a decisão sobre se o comportamento corresponde ao que a aplicação deve fazer.

Se um resultado for inesperado, descreva a diferença ao agente usando o mesmo vocabulário: o comando, a decisão, o evento e a consulta. Isso dá-lhe um comportamento concreto para corrigir.

Para consultar a sintaxe, as orientações de testes, as notas de lançamento ou obter ajuda, use [Recursos e estado do projeto](../resources/).
