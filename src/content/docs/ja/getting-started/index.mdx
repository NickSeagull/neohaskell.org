<p class="docs-lead">環境を準備し、AI エージェントに小さく明確な最初のタスクを依頼します。</p>

コマンド、決定、イベント、クエリについて初めて学ぶ場合は、まず[基本概念](/learn/)を確認してください。このガイドでは同じショップの例を使い、在庫があれば注文を受け付け、売り切れていれば拒否します。

## 環境を準備する

**Neo CLI** はアプリケーションの作成、ビルド、実行、テストを行います。[前提条件とインストール手順](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/README.md#prerequisites)では Nix と Git が必要とされています。ソースからインストールする手順では、Rust の Cargo も使用します。エージェントスキルをインストールする前に、[プロジェクトの作成と実行ガイド](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/project-and-cli.md#create-and-run-an-application)に従ってアプリケーションのリポジトリを作成してください。

最初に Counter アプリケーションを確認する場合は、[スターターの要件とクイックスタート](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/starter/README.md#requirements)を読んでください。デフォルトのイベントストアはメモリ内にあり、プロセスが終了すると記録されたイベントは消えます。[ストレージガイド](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/storage.md)では永続ストレージの選択肢を説明しています。

これらのリンクは、確認時点のフレームワークのリビジョンについて説明しています。アプリケーションが固定しているバージョンに合った手順を使ってください。エージェントスキルのインストーラーには、別途 **Node.js 22.20 以降**が必要です。

続ける前に、アプリケーションのリポジトリを開き、コーディングエージェントがそのリポジトリで作業できる状態にしてください。現在のスキル集は **Claude Code** と **Codex** に対応しています。

## エージェントスキルをインストールする

NeoHaskell のスキルは、コーディングエージェントにプロジェクト固有のガイダンスを提供します。アプリケーションの Git ルートで次のコマンドを実行してください。

```sh title="ターミナル" wrap
npx skills add neohaskell/skills --skill '*'
```

インストーラーでは、使用するエージェントとインストール範囲を選びます。関連するスキルやリソースをまとめて利用できるよう、スキル集全体を選択してください。インストールされたファイルとロックファイルはプロジェクト内に保持してください。

コマンドとインストーラーの要件は、2026年11月9日に確認した [NeoHaskell skills README](https://github.com/neohaskell/skills/blob/0ff0872d554e79d955f4c92f9b905056b908e9ae/README.md)に記載されています。更新情報は[最新のインストール手順](https://github.com/neohaskell/skills#readme)で確認してください。

## 最初のタスクを説明する

実現したい動作と、コマンドを受け付けられない場合にどうするかをエージェントに伝えてください。ショップの例では、次のタスクを使えます。

```text title="エージェントへのタスク例" wrap
顧客が陶器のマグカップを1個注文できるようにしてください。

数量が正で、在庫が足りている場合に限り注文を受け付けてください。

受け付けた注文を OrderPlaced として記録し、残りの在庫を返すクエリを用意してください。

在庫が足りない場合は、受け付けた注文のイベントを記録せずにコマンドを拒否してください。

受け付けた場合と拒否した場合の両方を確認してください。
```

まずはこの1つの動作から始めてください。最初の結果を確認できたら、支払い、配送、その他の条件を別々の変更として追加します。

## 結果を確認する

注文が受け付けられる場合と拒否される場合の両方をエージェントに示してもらいます。それぞれ次の在庫数から始めて、結果がモデルと一致するか確認してください。

| 開始時の在庫 | コマンド | 期待されるイベント | 注文後の在庫 |
| --- | --- | --- | --- |
| マグカップ3個 | マグカップを1個注文 | `OrderPlaced` | マグカップ2個 |
| マグカップ0個 | マグカップを1個注文 | 受け付けた注文のイベントなし | マグカップ0個 |

数量が0または負の場合も拒否されることを確認してください。技術的なチェックで実装上の間違いを見つけられますが、動作がアプリケーションに求めるものと一致するかは、あなた自身が判断します。

結果が予想と違う場合は、同じ用語を使って違いをエージェントに説明してください。コマンド、決定、イベント、クエリを具体的に示すと、修正する動作が明確になります。

構文、テストのガイダンス、リリース情報、サポートについては、[リソースとプロジェクトの状況](/resources/)を確認してください。
