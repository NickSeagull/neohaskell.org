<p class="docs-lead">環境を準備し、範囲を明確にした小さなタスクをAIエージェントに依頼します。</p>

コマンド、判断、イベント、クエリが初めてなら、[コードの背後にある仕事](../introduction/)から始めてください。このガイドでは同じショップを例に、在庫があれば注文を受理し、売り切れていれば拒否します。

## 環境を準備する <a id="prepare-your-environment" />

**Neo CLI**はアプリケーションの作成、ビルド、実行、テストに使います。[前提条件とインストール手順](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/README.md#prerequisites)にはNixとGitが記載されています。文書化されているソースからのインストールでは、RustのCargoも使います。エージェントスキルをインストールする前に、[プロジェクトの作成と実行ガイド](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/project-and-cli.md#create-and-run-an-application)に従ってアプリケーションのリポジトリを作成してください。

まずCounterアプリケーションを確認する場合は、[スターターの要件とクイックスタート](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/neo/starter/README.md#requirements)を読んでください。既定のイベントストアはメモリ内にあり、プロセスが終了すると記録されたイベントは消えます。[ストレージガイド](https://github.com/neohaskell/NeoHaskell/blob/cacc8069070721539ae0aac53286ce9492e906a5/docs/agent/storage.md)では永続ストレージの選択肢を説明しています。

これらのリンクは、確認済みのフレームワークリビジョンに関するものです。アプリケーションが固定しているバージョンに対応した手順を使ってください。エージェントスキルのインストーラーには、**Node.js 22.20以降**も必要です。

続ける前に、アプリケーションのリポジトリを開き、その中で作業できるコーディングエージェントを準備してください。現在のスキル集は**Claude Code**と**Codex**に対応しています。

## エージェントスキルをインストールする <a id="install-agent-skills" />

NeoHaskellのスキルは、コーディングエージェントにプロジェクト固有のガイダンスを提供します。アプリケーションのGitルートで次のコマンドを実行してください。

```sh title="ターミナル" wrap
npx skills add neohaskell/skills --skill '*'
```

インストーラーで、使用するエージェントとインストール範囲を選びます。関連するスキルとリソースをまとめて利用できるよう、すべてを選択してください。インストールされたファイルとロックファイルはプロジェクトと一緒に管理します。

コマンドとインストーラーの要件は、2026年11月9日に確認した[NeoHaskell skillsのREADME](https://github.com/neohaskell/skills/blob/0ff0872d554e79d955f4c92f9b905056b908e9ae/README.md)に基づいています。更新情報は[現在のインストール手順](https://github.com/neohaskell/skills#readme)で確認してください。

## 最初のタスクを伝える <a id="describe-a-first-task" />

実現したい動作と、コマンドを受理できない場合に何が起こるべきかをエージェントに伝えます。ショップの例には、次のタスクを使えます。

```text title="エージェントへの依頼例" wrap
お客様が陶器のマグカップを1個注文できるようにしてください。

数量が正で、在庫が足りる場合に限り、注文を受理してください。

受理した注文をOrderPlacedとして記録し、残りの在庫を返すクエリを用意してください。

在庫が足りない場合は、受理された注文のイベントを記録せずにコマンドを拒否してください。

受理された場合と拒否された場合の両方を確認してください。
```

まずはこの1つの動作から始めます。最初の結果を確認できたら、支払い、配送、その他の条件を別の変更として追加してください。

## 結果を確認する <a id="check-the-result" />

受理される注文と拒否される注文の両方を実演するようエージェントに頼みます。それぞれ、次の開始時在庫を使い、結果をモデルと照らし合わせてください。

| 開始時の在庫 | コマンド | 予想されるイベント | 処理後の在庫 |
| --- | --- | --- | --- |
| マグカップ3個 | マグカップ1個を注文 | `OrderPlaced` | マグカップ2個 |
| マグカップ0個 | マグカップ1個を注文 | 受理された注文のイベントなし | マグカップ0個 |

数量がゼロまたは負の場合も拒否されることを確認してください。技術的なチェックで実装ミスを見つけられますが、動作がアプリケーションに必要なものかどうかは、あなたが判断します。

予想と違う結果が出たら、同じ用語を使って違いをエージェントに伝えてください。コマンド、判断、イベント、クエリを具体的に示すことで、修正すべき動作が明確になります。

構文、テストのガイダンス、リリースノート、ヘルプについては、[リソースとプロジェクトの状況](../resources/)を参照してください。
